# G14 — Локальная диктовка GigaAM v3

## Проблема и решение

Илья хочет надиктовывать текст по горячей клавише в любом приложении, как в приложениях на Whisper, используя GigaAM v3. Выбран локальный режим: запись не покидает Mac, после однократной загрузки модели интернет не нужен.

Пользователь выбрал: «Держу клавишу — записывает, отпустил — текст вставился.» Рабочее сочетание по умолчанию ⌃⌥Space: keyDown начинает запись, отпускание основной клавиши либо любого обязательного модификатора заканчивает запись и запускает распознавание. Результат вставляется без Enter. Сочетание переназначается в существующем окне. Esc отменяет запись/распознавание. Режим toggle не нужен. Хоткей только из модификаторов тоже должен начинать на полном нажатом наборе и завершать на его отпускании; голая клавиша не допускается, конфликты с существующими жестами отклоняются.

## Пользовательские истории и приёмка

1. В меню есть «Диктовка»: первая настройка показывает размер загрузки, прогресс, отмену, ошибки и повтор. Нет загрузки модели при обычном старте переключателя.
2. После загрузки ~233 MB проверенных весов и разрешения микрофона пользователь запускает запись горячей клавишей. Индикатор показывает запись и распознавание, не отбирая фокус у поля.
3. Отпускание сочетания останавливает запись и начинает локальное распознавание GigaAM v3 E2E RNNT со знаками препинания. Автоповтор удерживаемого сочетания не переключает состояния.
4. Результат вставляется в прежнее поле без Enter, без изменения буфера обмена, без автоисправления распознанных слов. Словесный буфер переключателя сбрасывается. Новые физические клавиши не перемешиваются с синтетической вставкой.
5. Если приложение/поле поменялось во время распознавания, текст не вводится в случайное место: результат доступен в окне с явной кнопкой копирования. Не логировать распознанный текст или аудио.
6. Esc, пауза и выход останавливают запись и завершают процесс распознавания; поздний результат отменённой сессии никогда не вставляется. Повторная попытка работает после ошибки/отмены. Временные записи удаляются.
7. Нет микрофона/отказ в разрешении/нет речи/нет модели/повреждена модель/ошибка движка — понятное сообщение и возможность повторить; не зависать в состоянии «Запись».
8. Secure Input блокирует начало диктовки и вставку. Пауза приложения отменяет текущую диктовку. Исключения автоматики раскладки не запрещают ЯВНО запрошенную диктовку в редакторах, но ввод в защищённые поля запрещён.
9. Ограничение записи 5 минут с видимым временем; при достижении лимита завершить и распознать. Длинное аудио (>25 секунд) проверяется реальным движком, не молча обрезается.
10. Настройки хоткея совместимы со старым config.json. Конфликт с конвертацией/авто отвергается, голая печатная клавиша для диктовки не принимается. Во время записи нового сочетания глобальная диктовка не запускается.
11. Существующая работа RU/EN, Enter, Shift+Enter, snippets, Option и обновления сохраняется. Индикатор диктовки сосуществует с RU/EN.
12. Установка .app/.dmg включает движок; пользователю не нужен Python/Homebrew. Mac Apple Silicon/macOS 13.4+ поддерживается. На Intel и macOS 13.0–13.3 приложение переключает раскладку как раньше, диктовка явно недоступна. Никакого тихого перехода на другую модель или сервер.

## Технические решения

- Узкое исключение к прежнему «без зависимостей»: для новой, явно заказанной ML-функции используется фиксированная GigaSTT 2.17.0 (MIT), нативная обёртка GigaAM v3 через ONNX Runtime. Детектор раскладки остаётся детерминированным и независимым.
- SwiftPM-зависимость только на macOS arm64. Linux ядро и тесты не должны скачивать Apple XCFramework. Intel сборка также без него. Версия точная, Package.resolved отслеживается.
- Бинарный XCFramework проверен: часть статических объектов требует macOS 13.4 несмотря на Package platforms 13.0. Helper собирается с deployment target 13.4; основное приложение остаётся macOS13, UI гейт 13.4.
- Отдельный встроенный executable SpeechRecognizer связывается с GigaSTT. Приложение запускает Process с currentDirectoryURL на приватную временную папку записи, передаёт basename WAV и абсолютный modelDir. Это удовлетворяет ограничениям transcribeFile (относительный путь внутри CWD), не меняя CWD главного приложения. stdout — структурированный результат, stderr — диагностические ошибки без речи; таймаут, ограничение вывода и terminate/kill при отмене.
- Запись AVFoundation, разрешение NSMicrophoneUsageDescription в бандле. Запись во временный WAV, не микрофон в служебном процессе. Работа с моделью/диском/ASR вне callback EventTap и главного потока.
- Веса в Application Support, вне заменяемого .app; последовательная загрузка URLSession, SHA256 каждого файла, атомарная установка, проверка полноты, отмена очищает временное. Обновление приложения не стирает веса.
- Для вставки используется общая очередь Typist и маркированные Unicode-события; без clipboard и без отправки сообщений. Вставка проверяет фокус и защищённый ввод; при невозможности результат показывается пользователю. Нужно исключить сохранённый устаревший undo/word buffer.
- Состояния диктовки и переходы тестируются через публичный платформонезависимый интерфейс SwitcherCore; существующий тестовый шов. Реальный ASR проверяется публичным русским WAV, успешность не подменяется тестовым текстом. Микрофон/внешние поля — ручная проверка на Mac, не заявлять её пройденной без факта.

## Проверка и поставка

Исходная macOS-сборка v1.2.0 прошла на Mac arm64/macOS 15.6.1/Swift 6.1.2. XCTest здесь отсутствует в CLT: запускать swift test на существующем Linux-сервере с Swift 6.0.3; не устанавливать Xcode. Mac — сборка/debug/release, подпись/DMG, реальный ASR на fixture. Релиз только после двух ревью и исправлений: VERSION 1.3.0 → commit → push main → git archive на сервере в штатное место. Пользовательскую установку не заменять до готового проверенного артефакта.
