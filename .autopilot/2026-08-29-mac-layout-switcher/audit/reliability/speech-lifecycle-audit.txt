PRIORITIZED FINDINGS

1. [P1] Failed self-update leaves the entire switcher stopped without recovery.
Sources: Sources/MacLayoutSwitcher/System/Updater.swift:209-221; tools/self-update.sh:23,38-56,61-72,100.
The UI starts a detached script and immediately terminates NSApp. The script runs under set -euo pipefail and only invokes open after every download/extract/build/install step succeeds. Its EXIT trap cleans temporary directories but never restarts the still-valid old application or reports the failure to the user. An ordinary network outage, corrupt/incomplete archive, or failed Swift build therefore removes all auto conversion, Option and dictation service until manual reopening. The on-disk bundle is preserved, but the working app is not restored.
Owned executable reproduction: /tmp/mls-g26-lifecycle-audit/run-update-fixture.py, /tmp/mls-g26-lifecycle-audit/update-results.json.
Compiled/executed production script is byte-for-byte except LOG is redirected to an owned /tmp path. Stub curl supplies only owned archives or exits6; stub open logs its calls. No network, installed bundle, real app, or user log modified.
Results:
- offline: exit6, old executable preserved, relaunch calls0
- invalid archive: exit1, old executable preserved, relaunch calls0
- build failure: exit71, old executable preserved, relaunch calls0
- success control: exit0, new executable installed, relaunch calls1
Recommended ticket acceptance: failure after user approves update retains/restores a running old version and visibly reports failure; success launches the intended new version after old process shutdown. Test all three failure stages and successful replacement with owned bundles/launch seam.

2. [P2] Leaving hotkey recording open disables every feature in other applications.
Sources: Sources/MacLayoutSwitcher/UI/HotkeyRecorderWindow.swift:127-140,190-218; Sources/MacLayoutSwitcher/Engine.swift:36-46,225-228; main.swift:180-183 (onRecordingChanged wiring).
Recording sets Engine.isRecordingHotkey=true, making all subsequent Engine input return .pass before dictation and layout hotkey logic. The recorder only installs a local NSEvent monitor and clears the flag on a completed recording, Esc in its own app, or closing the window. It has no windowDidResignKey/applicationDidResignActive handling. Clicking Record then switching to another application leaves the global feature-disable flag active, while the local monitor cannot receive that other app's normal keystrokes. Automatic conversion, Option and dictation remain unavailable until the recording is finished or its window closed.
Owned headless reproduction: /tmp/mls-g26-hotkey-probe/main.swift, run.log, probe.
Production Config and HotkeyRecorderWindow compiled unchanged, production SwitcherCore compiled locally. Creates only headless NSButton/NSApplication(.prohibited), invokes actual @objc startRecording, delivers local resign-active/resign-key notifications, then actual windowWillClose. No shown window, external AX, global input, app activation, or TCC changes.
Output:
recording_after_app_and_window_resign=true, callback_history=[true]
recording_after_close=false, callback_history=[true, false]
This proves flag lifetime; effect on Engine follows the unconditional production gate above. It does not claim a live cross-app reproduction.
Recommended ticket acceptance: recording ends or is suspended when its window/application loses focus, without leaking the recorded chord into conversion/dictation; close/Esc/normal finalize still clear the flag.

3. [P2] Failed resume reports active status despite a missing event tap.
Sources: Sources/MacLayoutSwitcher/main.swift:87-90; Sources/MacLayoutSwitcher/UI/StatusBarUI.swift:226-229; Sources/MacLayoutSwitcher/Engine.swift:134-142.
Initial startup checks engine.start() and displays onboarding on failure. The Pause->Resume callback discards the same Bool, while StatusBarUI already toggles paused=false and main updates the active indicator. Engine.start also sets dictation.paused=false and starts focus sampling before tap.start can fail. If the event tap cannot be recreated (for example permission was revoked while paused), the app looks resumed but no input reaches auto correction, Option, or dictation. No explanation/recovery path is invoked.
Evidence level: direct source control-flow proof. I did not revoke permissions or make live event taps fail, per task constraints; no runtime TCC reproduction is claimed.
Recommended ticket acceptance: only show resumed state after successful tap start; preserve truthful paused/failed status and surface permission or startup failure, with no focus sampler left active on failed start. Exercise injected start=false and later recovery=true.
