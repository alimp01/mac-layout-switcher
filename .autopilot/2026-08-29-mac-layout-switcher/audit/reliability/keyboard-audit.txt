[P1] Normal navigation is misclassified as text and may inject C0 control text while a replacement is pending.
Location: Sources/MacLayoutSwitcher/Engine.swift:538-546 (root); replayPress:404-408 and busy handling:343-364 (effect).
Trigger: Start an automatic word correction, then press a normal non-autorepeat Left/Right/Home/End/Esc/F key while the worker owns the temporary source selection.
Production KeyTranslator returns one C0 character, not an empty string: Left U+001C, Right U+001D, Down U+001F, Up U+001E, Home U+0001, End U+0004, Esc U+001B, F1 U+0010. translate classifies it as .char; inputFocus is not invalidated; replayPress builds Unicode instead of preserving/cancelling the navigation key; the app receives the control character after the correction.
Repro: exact compiled EventTap→KeyTranslator→Engine→Typist, production core and focus/selection code, owned AppKit receiver; final CG post and system focus replaced with documented existing harness boundaries. On current RU input source, typed literal руддщ, began Space correction, injected normal Left in selectionHook. Observed: NONREPEAT_ARROW_DECISION suppress; AFTER_NONREPEAT_ARROW "hello \u{1C}" posted [0,0]. Required original unchanged and no synthetic posts (same expectation already established by autorepeat tests). Runner exits 1.
Evidence: /tmp/mls-keyboard-engine.d3iUU2/run.log; main.swift; source-provenance.json; seams.patch; SHA256SUMS. Minimal production KeyTranslator scalar probe: /tmp/mls-g26-keyboard-audit-probe/main.swift and probe binary (no changes to actual layout).
Why existing tests missed it: tools/keyboard-harness/engine.swift:394-400 uses autorepeat:true for every navigation case, forcing translate to .reset at Engine:532 before control classification. textEditingRepeat already rejects controlCharacters at Engine:395, but the ordinary translate path does not.
Fix direction: classify control scalars as reset after explicitly allowing boundary characters and Backspace; preserve pass/cancellation for ordinary navigation. Add both non-repeat and repeat cases on both AX/Unicode replacement routes; include quiet-buffer reset and pending Option. No need for dictionary or transport change.
This finding is not claimed to explain the initial unavailableField user error. It is an additional reproducible integrity failure discovered by the comprehensive audit.

[P2] Event tap interruption retains consumed shortcut ownership and suppresses the next fresh ordinary key when its keyUp was missed.
Location: Sources/MacLayoutSwitcher/System/EventTap.swift:123-129; Sources/MacLayoutSwitcher/Engine.swift:197-209. resetPhysicalInputState exists at Engine:157-165 but is not invoked for tap interruption.
Trigger: Configured ordinary convert shortcut CmdShiftK has its down consumed; tap becomes disabled before its keyUp reaches Engine; tap is re-enabled; user presses unmodified K.
Repro: same production EventTap→Engine harness; custom fixture config uses Hotkey(keyCode:40,modifiers:[.command,.shift]); invoke consumed keyDown; send tapDisabledByTimeout to production EventTap.process; omit keyUp to model suspension; fresh unmodified K down returns suppress. Required pass. Runner exits 1 with POST_TIMEOUT_FRESH_KEY_DECISION suppress.
Evidence: /tmp/mls-keyboard-engine.ypfecB/run.log; main.swift; source-provenance.json; seams.patch; SHA256SUMS.
Cause: timeout maps to generic contextChanged (same as clicks), whose Engine branch invalidates focus but leaves shortcutKeysDown/suppressedKeyUps/dictationGesture intact. Next down hits stale shortcutKeysDown before normal processing. First fresh K/up clears the stale ownership, but that real keystroke is lost. Existing comment explicitly says ownership must not survive suspension.
Fix direction: distinguish tap interruption from mouse context change and synchronously reset physical ownership/gestures on suspension. Review dictation cancellation on interruption without starting mic in tests. Do not blindly reset shortcut ownership for every mouse click, because a physically held shortcut may still own its repeats/keyUp.
