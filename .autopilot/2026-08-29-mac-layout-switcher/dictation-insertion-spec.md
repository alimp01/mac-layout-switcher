# G19 — вставка диктовки и видимый результат

## Проблема и доказательства
Пользователь на1.4.1 получает fallback «Автовставка недоступна или поле изменилось», но текст визуально отсутствует. В текущем Coordinator этот fallback достижим только после непустого распознавания либо с непустым невставленным остатком. Разделить сбой показа результата и отказ захвата/проверки поля; не называть это доказанной ошибкой модели или разрешений без проверки.

## Критерии
1. В доступном редактируемом поле запись удержанием → отпускание → ровно одна вставка распознанного текста в исходное поле, без Enter/Tab, без подмены всего значения поля. Кириллица, emoji, длинный текст и выделение не теряются. Слой распознавания остаётся local GigaAM без новых зависимостей и повторных загрузок.
2. Проверить совместимость захвата с полями Electron/Chromium (включая Codex), native NSTextView и browser contenteditable. Обоснованные bounded AX retries/инициализация accessibility допустимы при наличии permission, вне tap/main; ни одной вставки лишь по совпадению PID. Отсутствие AXSelection не приравнивать автоматически к смене фокуса: поддержать безопасный вариант только при доказуемой идентичности редактора и отсутствии вмешательства, иначе понятный fallback. Исследование API подкрепить primary docs/source.
3. Изменение фокуса/поля/выделения/ввод пользователя во время записи/распознавания, Esc/пауза/secure input отменяют право вставки. Возврат в то же поле не должен оживлять устаревшее разрешение. Нельзя ослаблять безопасность исправления раскладки/конвертации выделения. Не писать, не печатать и не логировать пользовательский текст диагностикой.
4. Невставленный результат всегда виден и выделяем в панели, в том числе длинный/многострочный, доступна прокрутка. «Копировать» копирует именно показанный текст и только после явного клика; автоматическая вставка не трогает clipboard. Панель не отнимает фокус при записи/распознавании. Отсутствие речи, отсутствие Accessibility, недоступное поле и смена поля не выдаются за одну причину, где причину можно достоверно отличить.
5. Не считать сам факт CGEvent.post подтверждением доставки. Выбрать проверяемый путь вставки/отказа, предотвратить дублирующий retry после возможной частичной вставки. Если сохранён CGEvent fallback, честно обосновать границы подтверждения и сохранения невставленного результата.
6. Регрессии воспроизводят исходные проблемы, а не только тестируют новый helper. Native AppKit harness подтверждает реальные размеры/document layout/glyphs и nonempty rendered fallback без микрофона/печати в пользовательских приложениях; injectable adapter/pure policy либо native fixtures проверяют AX capability/focus/cancellation/insertion failure. Публичное ядро: полный Linux suite; Mac native release;2 независимых ревью. Живую приёмку в пользовательском Codex не объявлять пройденной без разрешённого фактического выполнения.
