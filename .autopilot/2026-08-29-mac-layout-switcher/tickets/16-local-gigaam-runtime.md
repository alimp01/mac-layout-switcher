# 16 — Локальная расшифровка WAV через GigaAM v3

**Требование:** G14
**Blocked by:** None — can start immediately
**Status:** done

## Что должно заработать

Готовая .app содержит нативный SpeechRecognizer: WAV → настоящий текст GigaAM v3 E2E полностью офлайн. В SwiftPM закреплена зависимость, Linux и Intel сборки не тянут Apple arm64 binary. Модель загружается штатным сервисом с прогрессом, отменой, проверкой хэшей и атомарной установкой; для проверки сервис доступен приложению T17.

Спецификация: ../speech-spec.md, технические решения и артефакты обязательны. Зона: Package.swift/Package.resolved, Sources/SpeechRecognizer, новые файлы System/SpeechModelStore.swift и System/SpeechRecognitionProcess.swift, build.sh, лицензии, README раздел backend, ADR 0012. Не трогать Engine/UI/main/config — T17.

- [x] CLI helper принимает model-dir + относительный WAV, выдаёт JSON текст/ошибку, nonzero при ошибке; настоящий GigaAM, не stub.
- [x] Публичный app-side процесс поддерживает timeout/cancel, не блокирует main/tap, не зависает на stdout/stderr; корректная изоляция CWD и temp cleanup.
- [x] Загрузчик четырёх закреплённых весов (233 MB) с прогрессом, cancel, SHA256/размером, атомарной установкой. Cache переживает обновление, ошибка/отмена не выглядит ready.
- [x] Сервис не начинает загрузку сам по старту приложения. Нет сетевых запросов при распознавании готовой модели.
- [x] build.sh пакует/подписывает helper и лицензии; старые функции/обновление не ломаются. Пока не бампать VERSION.
- [x] swift build на Mac; реальное распознавание публичного WAV, длинного WAV и тишины. Передать root точные команды и пути; не писать аудио/веса в git.
- [x] Два ревью до финального коммита (организует root). Исполнитель не пушит, не коммитит до сигнала root.
