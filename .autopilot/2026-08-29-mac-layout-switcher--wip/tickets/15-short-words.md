# 15 — Короткие частотные слова: «Как», «ты», «и»

**Требования:** G13 (расширяет R04i)
**Blocked by:** 02
**Зона:** `Sources/SwitcherCore/Detector.swift`, `Sources/SwitcherCore/ShortWords.swift` (новый), `Tests/SwitcherCoreTests/Detector*`, `Tests/SwitcherCoreTests/ShortWords*`
**Волна:** 12 (параллельно с T14 — НЕ трогать EngineCore/Engine/Typist/EventTap)
**Status:** ready

## Что должно заработать

Пользователь пишет по-русски в EN-раскладке: «Rfr ns b z» → «Как ты и я». Сейчас
слова <3 букв игнорируются, а «Rfr» не проходит биграммный порог. Должно:
короткие частотные слова исправляются, при этом валидные короткие английские
(«of», «to», «is», «a», «I», «it», «in», «on», «we») в английском тексте НЕ
трогаются, и валидные русские короткие («и», «в», «на», «не», «я», «он») в
русском тексте не трогаются.

## Из брифа, дословно

> «смотри еще он не правит например "Как" "ты" "и" и т.д. очень много слов он не правит»

## Детали

- **`ShortWords`** (новый файл в SwitcherCore): два зашитых множества —
  частотные русские слова длиной 1–4 (≈150: и, в, на, не, я, ты, он, мы, вы, как,
  что, это, так, все, был, для, его, она, они, но, да, нет, ну, же, бы, ли, от, до,
  по, за, из, у, к, с, о, а, о́, же, тут, там, вот, кто, где, когда(5 — нет), ещё,
  уже, или, если, чем, тем, сам, еще, есть, надо, …) и частотные английские 1–4
  (≈150: a, I, an, the, of, to, in, is, it, on, we, he, be, or, if, so, no, do, up,
  my, me, us, go, am, ok, id, at, by, as, and, are, for, you, not, but, can, all,
  was, has, had, one, two, out, get, got, now, new, use, see, way, who, how, its,
  yes, hi, ok, …). Регистр не важен (сравнение lowercased). Составь списки сам
  из общих знаний частотности — источник отметь комментарием. Включи в RU-список
  разговорные «ща», «щас», «ок», чтобы не было коллизий с EN.
- **Правило в `Detector.verdict`** (ДО порога длины/биграмм, после проверки
  алфавита и исключений):
  1. Слово из латиницы: `ru = KeyMap.convert(word, to: .ru).lowercased()`.
     Если `ru ∈ RU-short` и `word.lowercased() ∉ EN-short` и слово не выглядит
     валидным английским (для длины ≤4 достаточно «не в EN-short»; для
     остальных — прежняя логика) → `.ru`.
  2. Симметрично кириллица → `.en`.
  3. **Коллизия** (обе стороны — слова, напр. EN «a» ↔ RU «ф» — нет; найди
     реальные коллизии тестом по спискам) → решает **контекст**: Detector
     помнит `lastContextLang` — алфавит последнего слова, которое прошло через
     `verdict` и не было исправлено (валидное), либо целевой язык последнего
     исправления. Совпадает с одной стороной коллизии → её. Нет контекста →
     `.unsure`.
  4. Обычные слова длиной ≥3, не попавшие в словари, — прежний путь
     (правила невозможных сочетаний + биграммы) без изменений.
- Порог «<3 → unsure» остаётся только для слов, которых нет в словарях.
- Публичный шов: `verdict(for:)` тот же; добавь `resetContext()` (для тестов
  и для EngineCore на будущее — но EngineCore в этом таске НЕ трогай).
- **Тесты** (Linux): Rfr→.ru, ns→.ru, b→.ru, d→.ru, yt→.ru, jy→.ru, z→.ru;
  «of/to/is/it/in/on/we/a/I/the/and» → .unsure (не трогать) — при пустом контексте;
  русские короткие «и/в/на/не/я/он» → .unsure; контекст: после русского слова
  коллизионное слово решается в RU, после английского — в EN; регистр «Rfr»
  сохраняется конверсией (это KeyMap, но проверь end-to-end через verdict+convert);
  прежний корпус (77 слов) — 0 ложных срабатываний по-прежнему.

## Критерии приёмки

- [ ] ShortWords: два списка ≥120 слов каждый, регистронезависимо, источник в комментарии
- [ ] Rfr/ns/b/d/yt/jy/z → .ru; of/to/is/it/in/on/we/a/I → .unsure без контекста; русские короткие валидные → .unsure
- [ ] Коллизии решаются контекстом; без контекста → .unsure; resetContext() есть
- [ ] Прежний корпус 77 слов: 0 ложных срабатываний, точность на однозначных не упала
- [ ] Полный swift test зелёный; EngineCore/Engine/Typist/EventTap не тронуты
