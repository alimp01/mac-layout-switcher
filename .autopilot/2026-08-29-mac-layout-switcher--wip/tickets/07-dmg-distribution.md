## Что должно заработать

Пользователь получает `.dmg`, монтирует его, перетаскивает MacLayoutSwitcher.app
в «Программы» — обычная установка macOS-приложения. Из исходников это делается
одной командой на Mac.

## Из брифа, дословно

> «и сделай программы как подноценное приложение в виде dmg файла»

## Разделы спецификации

История 15 (G04); «Решения по реализации» (сборка).

## Детали

- **Новый скрипт `build-dmg.sh`** (bash, для macOS; на Linux не запускается —
  проверяй `bash -n`): сначала гарантирует наличие `dist/MacLayoutSwitcher.app`
  (вызвать `./build.sh`, если .app нет или флагом `--rebuild`), затем собирает
  `dist/MacLayoutSwitcher.dmg`.
- Красивый дистрибутив-образ: staging-папка, куда кладётся `MacLayoutSwitcher.app`
  и **симлинк на `/Applications`** (`ln -s /Applications "<staging>/Applications"`),
  чтобы пользователь перетащил .app на ярлык «Программы». Затем
  `hdiutil create -volname "MacLayoutSwitcher" -srcfolder <staging> -ov
  -format UDZO dist/MacLayoutSwitcher.dmg`. Staging убрать после.
- Имя тома и итогового файла — константами вверху скрипта. `set -euo pipefail`,
  `cd` в каталог скрипта, чистка временных на выходе (trap).
- **README** — добавь раздел «Установка через .dmg»: `./build-dmg.sh` →
  `open dist/MacLayoutSwitcher.dmg` → перетащить в «Программы»; и честно про
  **первый запуск без нотаризации**: правый клик по приложению в «Программах» →
  «Открыть» → подтвердить (Gatekeeper, т.к. подпись ad-hoc, нет Apple Developer ID);
  разрешения Универсальный доступ + Мониторинг ввода — как и для .app.
  Не удаляй существующие разделы README, дополни.
- В `build.sh` можно (не обязательно) в конце подсказать строкой: «для .dmg —
  ./build-dmg.sh». Логику dmg держи в отдельном скрипте, не раздувай build.sh.
- Никакого кода Swift — только скрипты и README. Зависимостей и внешних
  инструментов не добавлять: только штатные macOS `hdiutil`, `ln`, `cp`.
