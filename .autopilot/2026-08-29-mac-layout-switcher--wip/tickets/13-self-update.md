## Что должно заработать

Приложение раз в сутки (и по пункту меню «Проверить обновления…») сравнивает
свою версию с последней в GitHub (репо ПУБЛИЧНОЕ: alimp01/mac-layout-switcher).
Новее — алерт «Доступна версия X. Обновить?» → по клику: скачать исходники,
пересобрать, заменить .app, перезапуститься. Молча ничего не делает.

## Из брифа, дословно

> «давай через git b сделаем автоматическое обновление в приложении при появлении новых версий»
> уточнение: репо публично; «уведомить + обновить по клику»

## Детали

- **`VERSION`** (корень): одна строка semver, начни с `1.1.0`. **build.sh**
  читает её и подставляет в CFBundleShortVersionString (замени зашитую версию).
- **`Updater`** (macOS, #if os(macOS)):
  - `currentVersion` — из Bundle (CFBundleShortVersionString).
  - `fetchLatest(completion:)` — GET
    `https://raw.githubusercontent.com/alimp01/mac-layout-switcher/main/VERSION`
    (URLSession, таймаут ~10 с; сбой сети = молча ничего, лог NSLog).
  - Сравнение semver по компонентам (вынеси `SemVer.compare` в SwitcherCore —
    маленький чистый код, покрой 3-4 тестами на Linux: больше/меньше/равно/
    разной длины).
  - Проверка при старте (через ~1 мин после запуска, чтобы не мешать) и далее
    раз в 24 ч (Timer.scheduledTimer с большим интервалом — это не поллинг
    состояния, а суточная проверка, допустимо); плюс пункт меню
    «Проверить обновления…» (ручная проверка с алертом и при «версия
    актуальна»).
  - Новая версия → NSAlert: «Доступна версия X (у тебя Y). Обновить?
    Приложение пересоберётся и перезапустится (~1-2 мин)» [Обновить / Позже].
- **`tools/self-update.sh`** — bash, запускается приложением через Process
  detached (setsid/nohup, чтобы пережил выход приложения):
  1. mktemp-папка; скачать
     `https://github.com/alimp01/mac-layout-switcher/archive/refs/heads/main.tar.gz`
     (curl -fL); распаковать;
  2. `./build.sh` в распакованном (вывод в лог-файл
     `~/Library/Logs/MacLayoutSwitcher-update.log`);
  3. определить, куда ставить: путь текущего бандла передаётся аргументом
     из приложения (Bundle.main.bundlePath); `rm -rf` старого .app +
     `cp -R` нового на то же место;
  4. `open` нового .app; чистка mktemp; `set -euo pipefail`, при любом сбое —
     лог и НЕ трогать существующий .app (сначала собрать во временном, только
     потом заменять).
  - Скрипт кладётся в бандл (build.sh копирует его в Contents/Resources),
    приложение запускает копию из бандла во временную папку (скрипт заменит
    сам бандл — исполняемый файл не должен исчезнуть из-под bash: скопируй
    скрипт в mktemp и запусти оттуда).
- **Разрешения**: заменённый на том же пути .app с ad-hoc подписью потеряет
  TCC-доверие (Accessibility/Input Monitoring) — при первом старте новой
  версии сработает существующий онбординг. Напиши об этом честно в алерте
  обновления («после обновления macOS попросит заново выдать разрешения»)
  и в README.
- **README**: раздел «Автообновление» (как работает, где лог, что разрешения
  придётся подтвердить заново).
