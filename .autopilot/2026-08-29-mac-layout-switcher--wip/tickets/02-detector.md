# 02 — Детектор неправильной раскладки

**Требования:** R04i (R04i.1)
**Blocked by:** 01
**Зона:** `Sources/SwitcherCore/Detector*`, `Tests/SwitcherCoreTests/Detector*`
**Волна:** 2

## Что должно заработать

Ядро отвечает на вопрос «это слово набрано не в той раскладке?» — детерминированно
и с перекосом в осторожность: лучше промолчать, чем испортить валидное слово.

## Из брифа, дословно

> «давай напишем свой аналог» (carambra/punto — их суть и есть этот детектор)
> дополнение: «Авто + горячая клавиша»

## Разделы спецификации

История 3 (R04i.1); «Решения по реализации» — пункт «Детектор: правила
невозможных сочетаний + биграммные частоты».

## Детали

- `Detector.verdict(for word: String) -> Verdict`, `enum Verdict { case ru, en, unsure }`:
  слово выглядит как русское, набранное в EN-раскладке → `.ru` (надо исправить в RU);
  как английское в RU-раскладке → `.en`; иначе `.unsure` (не трогать).
- Сигналы, по убыванию силы:
  1. Алфавит: слово целиком из кириллицы или целиком из латиницы; смешанное → `.unsure`.
  2. Невозможные последовательности: для латинского кандидата — сочетания,
     не встречающиеся в английских словах (например `ghb`, `qw` в середине,
     три согласных типа `zhb`), но встречающиеся в транслите ЙЦУКЕН;
     симметрично для кириллицы (например «ыва», «фыв» как след QWERTY-набора,
     кириллические слова с «ъи», «йц» в начале).
  3. Биграммные частоты: лог-вероятность слова по таблице биграмм EN против
     лог-вероятности его конверсии по таблице RU (и симметрично). Таблицы —
     зашитые в код Swift-словари, сгенерированные из частотных списков
     (сгенерируй скриптом из открытых частотных данных или составь вручную
     из ~200 самых частотных биграмм каждого языка — источник зафиксируй
     комментарием). Разница ниже порога → `.unsure`.
- Слова короче 3 символов — всегда `.unsure`. Слова с цифрами/символами вне
  карты — `.unsure`.
- Исключения: `addExclusion(_:)`, `isExcluded(_:)`, load/save JSON (тот же
  стиль, что SnippetStore); слово из исключений → всегда `.unsure`.
  Сравнение без учёта регистра.
- Контрольный корпус в тестах: ≥60 слов — частотные русские в EN-наборе
  (ghbdtn, cgfcb,j, ghbrk.xtybt…), валидные английские (hello, the, question,
  id, ok, url…), валидные русские, спорные короткие. **0 ложных срабатываний**
  на валидных словах корпуса; ≥90% верных `.ru`/`.en` на однозначных.

## Критерии приёмки

- [ ] Контрольный корпус ≥60 слов: 0 ложных срабатываний, ≥90% попаданий на однозначных
- [ ] Короткие (<3), смешанные, с цифрами → `.unsure`
- [ ] Исключения работают и переживают перезагрузку из JSON
- [ ] `swift test` на Linux зелёный
- [ ] Пороги вынесены константами с комментарием «почему такие»
