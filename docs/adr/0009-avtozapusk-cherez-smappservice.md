# 0009. Автозапуск при входе через SMAppService

## Контекст

После сдачи пользователь попросил автозапуск: чтобы после перезагрузки Mac
приложение стартовало само, без ручного открытия (G06). Приложение —
меню-бар-агент (`NSApplication(.accessory)`, ADR не про UI), минимальная
macOS — 13 Ventura (ADR 0001). Нужен способ зарегистрировать приложение как
объект входа, управляемый из самого приложения, и отразить состояние в
меню-баре. Тумблер должен честно показывать реальный статус регистрации, а не
записанное намерение: пользователь может отозвать разрешение в системных
настройках, и меню обязано это увидеть.

## Решение

Регистрация объекта входа через `SMAppService.mainApp` (`register()`/
`unregister()`, доступно с macOS 13). Тумблер «Запускать при входе» в меню-баре,
дефолт — выключено; желаемое состояние хранится в `config.json`
(`launchAtLogin`, согласуется с ADR 0005). Источник истины для галочки —
фактический `status` службы, а не поле config: меню читает реальное состояние
регистрации. Если статус `.requiresApproval` (пользователь должен подтвердить в
системе), приложение показывает подсказку и открывает панель «Объекты входа»
(Login Items) в системных настройках.

## Почему

Нужен современный, живущий вместе с бандлом механизм автозапуска, состояние
которого можно честно прочитать. Рассмотрели и отвергли:

- **LaunchAgent plist в `~/Library/LaunchAgents`.** Требует вручную писать и
  укладывать XML-файл, который живёт отдельно от `.app` и не знает о нём: при
  перемещении или удалении приложения plist остаётся с устаревшим путём —
  рассинхрон и «мёртвый» объект входа. `SMAppService.mainApp` привязан к самому
  бандлу и снимается вместе с ним.
- **`SMLoginItemSetEnabled` + helper-бандл** (прежний штатный путь). Устарел
  (deprecated) с macOS 13 и требует вложенного отдельного helper-приложения
  внутри бандла ради одной регистрации — лишняя поверхность при минимальной
  macOS 13. `SMAppService.mainApp` регистрирует главное приложение напрямую, без
  helper'а.
- **Включать автозапуск по умолчанию.** Навязчиво: пользователь не просил
  стартовать при каждом входе без спроса. Отвергнут в пользу дефолта «выключено»
  — автозапуск включается осознанно тумблером.

## Последствия

- `config.json` получил поле `launchAtLogin` (согласуется с ADR 0005), но оно —
  лишь желаемое намерение; отображаемая истина берётся из `SMAppService.status`,
  поэтому отзыв разрешения в системе виден в меню без рассинхрона.
- Случай `.requiresApproval` не проглатывается тихо (в духе явных подсказок по
  разрешениям, как с Accessibility/Input Monitoring): пользователю показывается
  инструкция и открывается панель «Объекты входа».
- Функциональность целиком в macOS-слое и тестами не покрыта (ADR 0001):
  тестируемой платформонезависимой логики здесь нет, проверка — приёмкой на Mac.
