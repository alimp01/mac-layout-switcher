# 0013. Привязка исправления к полю и атомарная замена через AX

**Статус: принято, G15/G17.** Для замены слова уточняет ADR 0003/0011.

## Причина

Буфер и отмена не были привязаны к полю: tap не наблюдал клики/смену фокуса,
Enter/Tab оставляли прошлое слово, reset не сбрасывал язык детектора. Очередь
Backspace/Unicode могла продолжать печатать после навигации. Эти пути
воспроизводимы в коде; конкретная причина префикса на скриншоте пользователя
не установлена одним скриншотом.

## Решение

- Физические клики, перетаскивание, команды/навигация и прерывание tap
  отменяют поколение фокуса и сбрасывают слово/undo/язык. Enter/Tab сначала
  получают решение исправления, затем не оставляют старого undo.
- AX-фокус запрашивается на отдельной очереди, не в EventTap. Периодический
  снимок не переустанавливает привязку, пока Typist занят; после известного
  сброса новый запрос запускается на следующем обороте main loop.
- Исправление требует актуального целевого AX-элемента, пустого выделения,
  точного исходного текста перед курсором и начала слова (начало поля либо
  пробельный символ). Совпадение только хвоста более длинного слова не годится.
- Вместо серии Backspace используется выделение проверенного диапазона и
  **одна запись AXSelectedText**. Перед записью повторно проверяются
  фокус/диапазон/текст/разрешение. Весь AXValue поля никогда не переписывается.
  Отказ до записи не удаляет исходный текст; своё временное выделение
  восстанавливается, только если пользователь ещё не сменил его.
- Обычный пробел входит в ту же запись. Enter/Tab сохраняют физический keyCode
  и флаги, доставляются после записи либо после безопасного отказа в том же
  поле. Нет legacy-перепечатки после уже доставленного Enter.
- Ошибка исправления отменяет зависимые исправления отдельно от физических
  клавиш: уже подавленные реальные клавиши в текущем поле не теряются из-за
  неподдерживаемого AX. Старый callback не сбрасывает буфер нового поля.
- Реальные клавиши после явно поставленного в очередь Tab/Enter следуют
  обычному порядку CGEvent до опустошения этой очереди. Детектор для этой
  части очереди выключен; текст исправления не может воспользоваться новым
  направлением. Новый клик/команда отменяет это разрешение.
- Раскладка/звук/персист undo меняются лишь после успешной записи текста;
  неуспешное provisional-решение отменяет обучение исключениям.

## Ограничения

Недоступные или не поддерживающие запись AXSelectedText редакторы получают
исходный ввод без автоматической замены. Новый AX-снимок после переключения
поля может прийти после самых первых букв: при установлении привязки они
сбрасываются консервативно; проверка начала слова не допускает исправить
только хвост. AX и очередь событий macOS не дают общей транзакции: остаётся
узкое окно между последней проверкой и доставкой Enter/Tab, а отменённые
кликом физические клавиши не переадресовываются в произвольное новое поле.
Нативную работу доступности/выделения/физического ввода требуется проверить
на Mac с разрешениями; успешная компиляция не является такой приёмкой.
