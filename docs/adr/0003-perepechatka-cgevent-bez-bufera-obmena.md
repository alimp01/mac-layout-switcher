# 0003. Перепечатка синтетическими CGEvent, а не через буфер обмена

## Контекст

Исправляя слово, приложение должно удалить N уже набранных символов и ввести
правильные в новой раскладке — в любом стороннем приложении, без прав на его
внутренности.

## Решение

Исправление — последовательность синтетических `CGEvent`: Backspace ×N, затем
перепечатка правильных символов (Unicode-ввод). Свои события помечаются магическим
значением в `eventSourceUserData`, чтобы event tap их игнорировал (защита от цикла).
Буфер обмена не трогаем.

## Почему

Нужен способ, работающий одинаково везде и не разрушающий пользовательские данные.
Рассмотрели и отвергли:

- **Через буфер обмена (записать текст в pasteboard + Cmd+V).** Затирает то, что
  пользователь держит в буфере (текст, картинку, файл) — восстановление хрупкое и
  гонки неизбежны. Cmd+V перехватывают/переопределяют многие приложения, а где-то
  вставка форматируется иначе, чем набор. Побочный эффект «пропал мой буфер» —
  неприемлем для фоновой утилиты.
- **Accessibility API (AXUIElement: заменить значение текстового поля).** Многие
  поля (Electron, Java, кастомные вью, терминалы) не отдают редактируемое
  `AXValue`; поведение непредсказуемо от приложения к приложению. Синтетические
  нажатия — общий знаменатель.

## Последствия

- Перепечатка видима: в поле мелькают удаление и ввод; при лаге приложения символы
  могут прийти не в том порядке — Backspace-последовательность и тайминги приходится
  выверять на реальном Mac.
- Обязателен маркер `eventSourceUserData` и его проверка на входе tap — без него
  собственные события уйдут в бесконечный цикл исправления.
- В приложениях с автодополнением/автозаменой Backspace может удалить не то, что
  ожидалось; для таких (терминалы, IDE) действует автопауза (ADR из спеки, список
  bundle-id).
