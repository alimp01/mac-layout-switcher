# 0005. Состояние в JSON-файлах, без БД и без UserDefaults

## Контекст

Нужно хранить тумблеры, список приложений-исключений, шаблоны автозамены и
слова-исключения. Пользователь должен уметь править шаблоны и исключения руками, а
отдельного GUI-редактора в этой версии нет.

## Решение

Всё состояние — обычные JSON-файлы в `~/Library/Application Support/MacLayoutSwitcher/`:
`config.json` (тумблеры, исключения-приложения), `snippets.json` (шаблоны),
`exclusions.json` (слова). Правка шаблонов/исключений — пункт меню «Открыть …json».
config пишется атомарно с сортировкой ключей; битый/отсутствующий config → бэкап
`.broken` рядом и дефолты.

## Почему

Прозрачность и правимость руками без GUI. Рассмотрели и отвергли:

- **SQLite / встроенная БД.** Оправдана при больших объёмах и сложных запросах —
  здесь данных горстка. Пользователь не откроет и не поправит `.sqlite` текстовым
  редактором, а меню «Открыть snippets.json» именно на этом и держится. Лишняя
  зависимость/схема/миграции ради нескольких десятков строк.
- **`UserDefaults` (plist).** Непрозрачно и неудобно править: бинарный/служебный
  plist в `~/Library/Preferences`, кэшируется `cfprefsd` (правки мимо API теряются),
  «открой файл и поправь шаблоны» так не сделать.

## Последствия

- Формат — часть контракта с пользователем: он видит и редактирует эти файлы, значит
  переименование полей/переезд на другое хранилище требует явной миграции и бэкапа.
- Никакой конкурентной записи и транзакций: спасаемся атомарной записью config;
  ручная правка файла во время работы приложения может быть перетёрта следующим
  `save()`.
- Ручной ввод допускает синтаксически битый JSON — поведение задано явно (config →
  дефолты + `.broken`; snippets/exclusions → пустой набор), молчаливой потери нет,
  но и валидации сверх этого тоже нет.
